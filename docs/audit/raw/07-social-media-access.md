# Social Media Evidence Gathering for a PROSPECTIVE Client — Access & Ownership Reality Check

Retrieved: 2026-09-14 (all sources below fetched/searched on this date unless noted).

Framing per the research brief: this is an **access/ownership problem**, not a missing-tool problem. Every official platform API that returns rich insight data (demographics, engagement rate, ad spend) is scoped to accounts the caller has been granted a role on. The only exceptions are the transparency APIs (Ad Library) and plain public-page viewing, which is exactly what the current Playwright approach already does. Nothing below changes that conclusion — it just puts numbers on it.

### 1b. Can an agency pull Instagram insights for an account it does NOT manage?

**No — this is access-gated by design, not by API tier.**

- The `instagram_manage_insights` permission (and all Instagram Graph API insights/demographics permissions) is split into two access levels:
  - **Standard Access**: automatically granted, but only works for Instagram professional accounts the app owner already manages, or accounts belonging to people with a role on the app (developer/tester/admin). No review needed — but also no access to outside accounts.
  - **Advanced Access**: required to serve Instagram accounts the developer does not own or manage. This requires **both App Review and Business Verification** (see 1a above). [Overview of the Instagram API — Meta for Developers](https://developers.facebook.com/docs/instagram-platform/overview/) — retrieved 2026-09-14; corroborated by [Instagram API Advanced Access Approval Guide (2026) — singhamandeep.com](https://singhamandeep.com/instagram-api-advanced-access-approval/) — retrieved 2026-09-14. [second source unverified as primary but consistent with Meta's own overview page]
- Critically, **even with Advanced Access approved, the target account still has to explicitly authorize the app via OAuth and grant the permission** — "once approved, your app can access data for any real user who grants the permission." [same source] This means Advanced Access removes Meta's review gate but does **not** remove the requirement that the prospective client personally logs in and clicks "Allow." There is no path — documented or undocumented — by which Advanced Access alone lets an agency pull a stranger's follower demographics, engagement rate, or post-performance insights without that account holder's affirmative action.
- Audience/account insights (age, gender bracket, location, active hours) additionally require ≥100 followers on the target account and are returned only to the authenticated account owner or a person/app with a granted role — never by looking a handle up from outside. [Instagram Audience Demographics API — Phyllo](https://www.getphyllo.com/post/instagram-audience-demographics-for-influencer-marketing-platforms) — retrieved 2026-09-14. [unverified — vendor blog, but consistent with Meta's documented insights model]

**Conclusion for #1b**: There is no legitimate way, at any verification tier, to pull Instagram Graph API insights (follower demographics, engagement rate, post performance) for a prospective client's account without that client granting the app a role/OAuth consent. This is a hard access-control boundary, not a paperwork problem that money or patience resolves.

### 1c. What does the Ad Library API expose for ANY advertiser — no account access needed?

**Yes — confirmed. This is the one genuinely free, no-access-required, public data source.**

- The Meta Ad Library (`facebook.com/ads/library`) and its API (`Graph API /ads_archive` endpoint) are Meta's ad-transparency tools. Anyone can search by advertiser Page name, keyword, or domain and see **every ad currently running** on Facebook, Instagram, Messenger and Audience Network for that advertiser — **no login, no account role, no relationship to the advertiser required.** [Meta Ad Library — official tool](https://www.facebook.com/ads/library/api) — retrieved 2026-09-14 (page fetch failed with a socket error on this session, so treat as [unverified via direct fetch] though independently corroborated below); [Meta Ad Library: How to Use (2026 Complete Guide) — mida.so](https://www.mida.so/blog/meta-ads-library) — retrieved 2026-09-14. [unverified — third-party guide, but describes Meta's own public tool which matches known long-standing behavior]
- Fields returned by the API for a standard commercial ad: ad ID, advertiser Page name/ID, ad creative text/body, ad creative link titles/images/video reference, `ad_snapshot_url` (a link to the fully rendered archived ad), delivery start (and end) dates, publisher platforms (FB/IG/Messenger/Audience Network), and `ad_reached_countries` (required query parameter). [How to Use the Facebook (Meta) Ad Library API — apidog.com](https://apidog.com/blog/facebook-ad-library-api/) — retrieved 2026-09-14. [unverified — third-party synthesis of the official docs, not the primary developers.facebook.com page directly, since that page returned a 404/network error in this session]
- For political/social-issue ads only (not relevant to typical commercial clients), extra fields appear: spend range, impression range, funding-entity/byline, and (EU/UK) demographic and regional delivery breakdowns. **Targeting data (interests/behaviors) and performance metrics (CTR, CVR, ROAS) are never returned for any ad, of any type, to any caller** — that data stays private to the advertiser regardless of API access level. [same source]
- Authentication: a Graph API access token from a registered developer app is required to call the API endpoint (this is a low bar — not equivalent to Business Verification); the public web UI at facebook.com/ads/library needs no account or login at all. [How to Use the Facebook (Meta) Ad Library API — apidog.com](https://apidog.com/blog/facebook-ad-library-api/) — retrieved 2026-09-14. [unverified — third-party]
- Cost: free, no paid tier. [same source]

**Confirmed answer to the brief's core question**: "Is this business currently running ads, and what do the ads look like" is available today, for any advertiser, for $0, without any account access, verification wait, or client cooperation — via the Ad Library UI or API. This is the single highest-value, zero-cost, zero-access-friction data source in this entire research task and should be the one thing beyond current Playwright scraping that gets built.

## 2. Instagram/TikTok: current API tiers and third-party access for unmanaged accounts

### Instagram (recap/extension of §1b)
- Two tiers only: Standard Access (owned/managed accounts, no review) and Advanced Access (any account, but requires App Review + Business Verification **and** the target account's own OAuth consent). No tier exists that grants read access to an arbitrary unmanaged account's insights. [Overview of the Instagram API — Meta for Developers](https://developers.facebook.com/docs/instagram-platform/overview/) — retrieved 2026-09-14.
- Timeline: App Review approval "ranges from a few days to several weeks, with rejections being common on the first submission," on top of the Business Verification wait in §1a. [Meta App Review Rejected? The Complete 2026 Fix-It Guide — woopsocial.com](https://woopsocial.com/blog/meta-app-review-rejected-2026-fix-guide) — retrieved 2026-09-14. [unverified — third-party, but directionally consistent with the community-forum evidence above]

### TikTok
- **Research API**: restricted to qualifying academic institutions, ~4-week approval process, capped at 1,000 requests/day, and **explicitly prohibits commercial use** — not usable by a marketing agency at all. [TikTok API Rate Limits 2026 — getphyllo.com](https://www.getphyllo.com/post/tiktok-api-rate-limits-in-2026-quotas-errors-workarounds) — retrieved 2026-09-14. [unverified — vendor blog synthesizing TikTok's published terms]
- **Display API**: rate-capped (600 req/min per endpoint); daily aggregate caps exist but are unpublished and vary by an approval tier TikTok assigns case-by-case. **No self-serve upgrade path and no published SLA** for quota-increase or access-tier requests. [same source]
- EU-only regulatory pathway: the European Commission's DSA delegated act on vetted-researcher data access took effect 2025-10-29, following a finding that TikTok had not fully met its DSA researcher-access obligations — this is an EU academic-researcher channel, not something a commercial agency (in or outside the EU) can use for prospective-client social scans. [same source]
- Net effect: TikTok has **no official API path at all** for a third party to pull profile/engagement data on an account it doesn't run, commercial use is explicitly excluded from the one open program (Research API), and the closest thing (Display/Content Posting API access) is gated by an opaque, un-timelined manual review. [Is TikTok API Free? What Happened and What Developers Use Instead — sociavault.com](https://sociavault.com/blog/tiktok-api-free-2026) — retrieved 2026-09-14. [unverified — vendor blog, but the underlying claim (no commercial-use official access) matches TikTok's documented Research API terms above]

## 3. Google Business Profile: unauthenticated lookup vs. API + ownership

### What's visible with zero access, right now, via plain Google Search/Maps
- Google Maps location pages (ratings, review text, review count, category/type, hours, photos, popular times) are **publicly visible in any browser, no login needed** — this is exactly the surface Playwright can already read today. [How to scrape Google Maps Reviews — wiserreview.com](https://wiserreview.com/blog/how-to-scrape-google-maps-reviews/) — retrieved 2026-09-14. [unverified — third-party guide, but the underlying fact (Maps listings are public) is common knowledge/observable]
- Legal framing: Google's ToS prohibit automated access "except where expressly permitted," but scraping publicly-visible, non-authenticated content has been treated as lawful for research/analysis under the *hiQ v. LinkedIn* Ninth Circuit precedent (automated access to public web data does not violate the US Computer Fraud and Abuse Act). A ToS breach is a contract matter, not a criminal one. [same source, plus general knowledge of hiQ v. LinkedIn, 9th Cir. 2019/2022] [unverified — legal characterization from a scraping-vendor blog, not counsel; should not be treated as legal advice]
- A relevant recent case: on 2026-07-20 a court granted SerpApi's motion to dismiss DMCA claims over scraped Google search-result content — reinforces that scraping *public, non-copyrighted* listing metadata (ratings/counts, not full review-photo reproduction) sits in defensible territory, though this is not the same as a blanket "scraping is fine" ruling. [same source] [unverified — case name/date not independently confirmed against a court record in this session]

### What requires the Business Profile API + ownership
- Every Business Profile API call is OAuth-scoped to accounts/locations the authenticated user has explicit ownership or management rights over — there is no "look up any location's API data" mode. [Manage verification — Google Business Profile APIs, developers.google.com](https://developers.google.com/my-business/content/manage-verification) — retrieved 2026-09-14. This IS the official Google documentation, so treat as verified.
- To even get **API access approved** for locations you do manage, Google requires: a formal access request, a demonstrated legitimate use case, a Google Cloud project, **and a verified profile that has been active for 60+ days with a matching business website** — before you can pull data even for your own client's profile via API. [Google Business Profile API Access Guide for Agencies — localith.ai](https://localith.ai/blog/google-business-profile-api-guide/) — retrieved 2026-09-14. [unverified — third-party summary, not the primary Google page, but directionally consistent with Google's documented OAuth-scoping model above]
- Verification methods for a location (postcard, phone, SMS, email) run through `locations.verify` and are inherently an ownership-proving workflow — not something a prospecting agency can or should attempt on a prospect's listing. [Manage verification — developers.google.com](https://developers.google.com/my-business/content/manage-verification) — retrieved 2026-09-14. Verified (official doc).

### Middle ground: Google Places API (no ownership needed, but costs money)
- The **Places API** (distinct from the Business Profile API) lets anyone query a public place by place_id/name and returns rating, `user_ratings_total`, category (`type`), business_status, address, and (Atmosphere tier) price_level and a handful of reviews — **without any ownership or verification**, just an API key and billing. [Place Details (Legacy) — Google for Developers](https://developers.google.com/maps/documentation/places/web-service/legacy/details) — retrieved 2026-09-14. Verified (official doc) for the field list; pricing figures below are third-party.
- Pricing (2026, per third-party trackers, not the official Google Cloud pricing page directly): Place Details "Basic" fields ≈ $17 per 1,000 requests (CPM); adding "Atmosphere" fields (rating, user_ratings_total, reviews) adds ≈ $5 CPM, so a full lookup with ratings ≈ $22 CPM (~$0.022/lookup), with volume discounts at 100K and 500K+ monthly tiers. [Google Places API Pricing 2026: Real Cost Per Session — woosmap.com](https://www.woosmap.com/blog/google-places-api-pricing) — retrieved 2026-09-14. [unverified — third-party pricing tracker; official pricing should be confirmed at cloud.google.com/maps-platform/pricing before committing spend]

**Bottom line for §3**: everything a proposal needs from Google (rating, review count, category, whether the listing looks maintained) is already visible via a plain unauthenticated Maps lookup — same territory as current Playwright scraping, and free. The Places API adds structured/reliable field access for a small per-call cost (~$0.02/lookup) with no ownership requirement — this is a viable low-cost upgrade. The Business Profile API is a dead end for prospecting: it is ownership-scoped by design and cannot ever return data about a location the agency doesn't manage.

## 4. Paid scraping/data providers — current 2026 pricing and ToS stance

All of these operate on public pages without the target's cooperation — they are a paid substitute for what Playwright does, not a way around the account-ownership walls in §1–3, and every one of them operates in tension with the platforms' own Terms of Service.

### Bright Data (Instagram Scraper API)
- Pay-per-success pricing: **$0.75 per 1,000 successful requests** for the Instagram Scraper API; proxies/rendering/unblocking bundled into that price. New accounts get 5,000 free credits/month (~$7.50 value). [Instagram Profiles Scraper — Bright Data](https://brightdata.com/products/web-scraper/instagram/profiles) — retrieved 2026-09-14. [unverified — vendor's own pricing page, generally reliable for current list price but not independently audited]

### Apify (Instagram actors)
- Pay-per-event model varies widely by actor: e.g., ~$0.00184/profile at "Bronze" reviewed-market rate for one actor; across the broader Instagram actor catalog (as of 2026-05-26): Post/Reel Scraper ≈ $1.00/1k, Followers Count ≈ $1.30/1k, general Instagram Scraper ≈ $1.50/1k, Profile Scraper ≈ $1.60/1k, Hashtag Scraper ≈ $1.90/1k. [Instagram Profile Scraper — Public Profile Details, Apify](https://apify.com/automation-lab/instagram-public-profile-details) and [Best Instagram Scrapers on Apify (2026) — use-apify.com](https://use-apify.com/docs/best-apify-actors/best-instagram-scrapers) — retrieved 2026-09-14. [unverified — third-party aggregation of Apify Store listings; prices are set per-actor by independent developers and change without notice]

### ScrapeCreators (multi-platform, incl. TikTok)
- Pay-as-you-go credits, no monthly minimum: 100 free credits on signup; $47 → 25,000 credits (~$1.88/1,000 calls); $497 → 500,000 credits (~$0.99/1,000 calls); credits don't expire; cache hits are free. Covers Instagram, TikTok, YouTube, Facebook, X, and others, including profiles, posts, and "ad-library data" endpoints. [Pay-As-You-Go Scraping APIs — scrapecreators.com](https://scrapecreators.com/blog/pay-as-you-go-scraping) — retrieved 2026-09-14. [unverified — vendor's own page]

### Phyllo (authenticated creator-data platform, mentioned as a comparison point)
- Entry point reported around **$199/month** for core API access, scaling with call volume/endpoints/platforms; enterprise pricing bespoke, not published. Phyllo is architecturally different from the scrapers above — it's built around the *creator* connecting their own accounts (OAuth), i.e., it solves the "client cooperates" case, not the "prospect hasn't agreed to anything" case. [Social Data API Pricing 2026 — getphyllo.com](https://www.getphyllo.com/post/social-data-api-pricing) — retrieved 2026-09-14. [unverified — vendor's own comparison blog]

### ToS/legal risk — explicit, not a footnote
- Instagram's Terms state: **"You may not access or collect data from our Products using automated means (without our prior permission) or attempt to access data you do not have permission to access."** This is a direct, current prohibition on exactly the scraping these vendors sell — Instagram explicitly reserves the right to suspend/terminate accounts and pursue enforcement against unauthorized automated collection. [Why your account has been restricted for data scraping — help.instagram.com](https://help.instagram.com/740480200552298/) — retrieved 2026-09-14. This is Meta's own help-center page, so treat the quoted clause as verified.
- Practical consequence: none of Bright Data/Apify/ScrapeCreators' Instagram or TikTok scraping is authorized by the platforms whose data they extract. The vendors carry the technical/proxy risk (IP bans, CAPTCHAs) and often indemnify nothing for the buyer; the legal exposure (ToS breach, potential account/IP bans on the agency's own infrastructure if self-hosted, and a live legal question — not yet fully settled the way hiQ v. LinkedIn settled logged-out public-page access — for aggressively-scraped, rate-limited, bot-detected platforms like Instagram/TikTok) sits with whoever operates the scraper or buys its output at scale. [General synthesis of the ToS text above + the ScrapeOps/legal commentary below] — [Is Instagram Scraping Legal? — scrapeops.io](https://scrapeops.io/websites/instagram/) — retrieved 2026-09-14. [unverified — vendor/industry commentary, not a legal opinion]

## Summary — what this system should actually do

**Free today, no client cooperation needed, and defensible:**
- Public-page scraping via Playwright (current approach) for follower counts, visible posts, bio text, brand consistency — this is public information, same legal footing as any browser visit.
- **Meta Ad Library (UI or `/ads_archive` API)** — confirmed free, no login, no account role, works for any advertiser Page. Directly answers "is this business running ads, and what do the ads look like" (creative, platforms, start date, `ad_snapshot_url`) with zero risk. This is the one clear addition worth building on top of the existing scraper.
- Plain Google Maps/Search lookup for rating, review count, category — already public, same territory as current scraping.
- Optionally, the Google **Places API** (not Business Profile API) for the same rating/review-count/category data with structured reliability, at roughly $0.02/lookup, no ownership required — a cheap, low-risk upgrade if scrape reliability is a problem.

**Requires the prospective client's own cooperation (a role/OAuth grant) — not obtainable any other way, at any verification tier or price:**
- Instagram/Facebook Graph API insights: follower demographics, engagement rate, post-performance analytics. Advanced Access removes Meta's review gate but the target account must still grant the permission via OAuth — there is no bypass.
- TikTok equivalent data: no official commercial path exists at all (Research API bars commercial use; Display API access is discretionary and un-timelined).
- Google Business Profile API data beyond what's on the public Maps page: hard-scoped to verified owners/managers.
- Meta Business Verification, where relevant, realistically runs anywhere from "a few days" (best case, per Meta's own copy) to 2+ months with no resolution (per open 2026 threads on Meta's own developer community forum) — not a dependable input to a sales-proposal timeline even where it's the correct path.

**Costs money and carries explicit ToS risk — a real option, but not a free one and not a compliant one:**
- Bright Data (~$0.75/1k), Apify (~$1–1.9/1k depending on actor), ScrapeCreators (~$1–1.9/1k credits) can technically pull deeper Instagram/TikTok profile and post data for an account the agency doesn't manage — but this directly contradicts Instagram's (and by extension TikTok's comparable) Terms of Service prohibiting automated data collection without permission, exposing the agency to account/IP enforcement action and unresolved legal risk beyond the narrower, more settled "public page view" precedent (hiQ v. LinkedIn) that covers simple Playwright scraping.

**Recommendation**: for a small agency automating its own sales proposals, the only unambiguous "yes, add this" is the **Meta Ad Library API** — it is free, requires no client cooperation, has no ToS conflict (it's Meta's own transparency product, designed for exactly this external lookup use case), and directly answers a question (are they running ads, what do the ads look like) the current Playwright scraper cannot answer at all. The Google Places API is a reasonable $0.02/lookup add-on if Maps scraping proves flaky. Paid Instagram/TikTok scrapers are not worth recommending: the deep data they'd add (engagement rate, demographics) is exactly the data that's still inaccessible without the client's cooperation regardless of scraper sophistication (a scraper cannot see a private insights dashboard), so the ToS/legal risk is being taken on for data that's often shallower than marketed and legally the shakiest tier of everything surveyed here.
