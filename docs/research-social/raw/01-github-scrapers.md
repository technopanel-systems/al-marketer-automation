# Open-source social-media scraper landscape (GitHub), 2026-09-14

Research task: find and evaluate the best currently-maintained open-source/free tools for pulling client + competitor social evidence (recent posts with date/format/likes/comments/views/caption, posting frequency, engagement) across Instagram, TikTok, LinkedIn company pages, Facebook pages, X, YouTube, Snapchat — for a low-volume (a few profiles per proposal), confidential, Windows + Node.js pipeline. Paid scraping APIs are out of scope by owner decision; this file is landscape research only, no paid tool is recommended.

**Methodology.** Repo metadata (stars, language, license, last commit = `pushed_at`, open issue count, archived flag) pulled directly from the GitHub REST API (`api.github.com/repos/...`) on 2026-09-14. Breakage/status claims are drawn from each repo's own Issues/Discussions pages (with specific issue numbers/dates where found), not from README marketing claims. Third-party "best scraper" blog posts (Scrapfly, Thunderbit, roundproxies, etc.) were used only to find candidates and cross-check star counts — their verdicts are noted as such, not treated as primary evidence, because several run/sell paid scraping infrastructure and have an incentive to describe free tools as broken. GitHub's unauthenticated REST API rate limit (60 req/hour) was exhausted partway through research; a few secondary repos are marked `[unverified]` for exact star/release numbers where I could not re-query in time — the qualitative status is still sourced.

## Cross-platform theme

Across every platform except YouTube and (mostly) TikTok, 2026 issue trackers show the same pattern: **logged-out scraping is a shrinking target**. Instagram, LinkedIn and X have all moved more of their public-facing data behind a login wall or aggressive rate limiting since 2023–2025, and Facebook's simplified "mbasic" front end (which most FB scrapers depend on) is fragile and can disappear or change without notice. This matches what the constitutional rules already assume ("Unknown stays unknown — never guess") — for Instagram/LinkedIn/X/Facebook, some fields will legitimately be unavailable for some profiles on some days, and the pipeline should treat that as expected, not as a bug to fix by adding a paid service.

**Instagram verdict:** Use **Instaloader** first for logged-out, low-risk collection of what's publicly visible (recent posts, dates, captions, approximate engagement). Fall back to **instagrapi** only when a field is missing and only from a disposable/burner research account that the agency is willing to lose — the maintainers themselves say checkpoint/ban is "the steady state," not an edge case. Do not rely on gallery-dl or yt-dlp as the primary Instagram path; they are fine opportunistic downloaders but both currently require login cookies for most content and gallery-dl had a multi-day outage inside this research window (fixed 2026-09-10).

## Notes on fit for this specific pipeline

- **CLI-first tools already exist for the strongest picks** (instaloader, gallery-dl, yt-dlp, youtube-comment-downloader, twscrape, StaffSpy) — these can be called directly from Node via `child_process.execFile`, matching the project's "Node.js 24, ES modules, minimal dependencies" convention without adding a persistent Python service.
- **Library-only Python tools** (instagrapi, joeyism/linkedin_scraper, twikit) need a small first-party Python wrapper script per platform that prints JSON to stdout — a normal, low-maintenance pattern, but it does mean the pipeline needs *some* Python 3 on the Windows machine (already true for the AI-step tooling elsewhere in this repo, per `python --version` returning 3.12/3.14 in this environment).
- **Self-hosted REST services** (Evil0ctal for TikTok, instagrapi-rest for Instagram) are the heaviest option (Docker containers, a database) and are probably overkill for "a few profiles per proposal" — worth keeping in mind only if the simpler CLI tools prove insufficient.
- **Account-based tools** (instagrapi, linkedin_scraper, twscrape, twikit) all need dedicated research accounts that are not the agency's or client's real accounts, sized for the fact that some of them will eventually get rate-limited, checkpointed, or banned — this is a operational/process requirement, not just a technical one.
