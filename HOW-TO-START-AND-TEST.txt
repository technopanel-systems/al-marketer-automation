AL-MARKETER PROPOSAL SYSTEM - START AND TEST (after restarting the computer)
===========================================================================

Project folder:  C:\dev\al-marketer-automation
App address:     http://localhost:4317

SHORT VERSION (normal restart)
  1. Double-click "Al-Marketer Control Center" on the Desktop.
  2. The app opens in your browser. Done.
  A restart loses nothing: every client, approval and PDF is saved in files.
  A step that was running when the computer shut down shows "Interrupted" -> click "Try again".


---------------------------------------------------------------
PART 1 - START THE APP
---------------------------------------------------------------

  1. Double-click "Al-Marketer Control Center" on the Desktop
     (or "Al-Marketer Control Center.cmd" inside the project folder).
  2. A black window opens and says:
       Al-Marketer Control Center: http://localhost:4317  (keep this window open; close it to stop)
     Your browser opens the app by itself.
     - After an update the first start may say "installing the free components" or
       "Downloading the free TikTok/YouTube reader". Wait until it finishes (a few minutes).
  3. The browser did not open?  Open  http://localhost:4317  yourself.
  4. Keep the black window open while you work. Close it to stop the app.
  5. Opened it twice by mistake? The second window says "already running", opens the app
     and closes. That is fine.


---------------------------------------------------------------
PART 2 - AFTER A RESTART: CHECK YOUR CLIENTS  (1 minute)
---------------------------------------------------------------

  1. The Proposals page shows "Needs you" (every task waiting for a person, with its button)
     and all proposals with their progress.
  2. A client shows "Failed", or a step says "Interrupted - the app or the computer was closed
     while this step was running":
       open the client -> click "Try again". Only that step runs again; finished work stays.
  3. A client says "Waiting for AI answer": Claude could not run -> see PART 4, problem A.
  4. You hit your Claude usage limit: wait until it resets, then click "Try again".
  5. Work that was ready when the app closed continues by itself when you start it again.


---------------------------------------------------------------
PART 3 - TEST THAT EVERYTHING WORKS
---------------------------------------------------------------

How to open a Terminal in the project folder (needed for tests 1-4):
  File Explorer -> go to C:\dev\al-marketer-automation -> right-click an empty area
  -> "Open in Terminal".

[ ] TEST 1 - Automated tests  (free, about 30 seconds, run this first)
    1. In the Terminal type:   npm test      and press Enter.
       If you see a red message "running scripts is disabled on this system", type:   npm.cmd test
    2. At the end, look for these lines:
         tests 193
         pass 193
         fail 0
       "fail 0" means everything is OK. (The number of tests grows after updates;
       what matters is fail 0.)
    3. Any "fail" above 0: copy the red lines and send them to Claude.

[ ] TEST 2 - Slide design  (free, about 5 seconds)
    1. In the Terminal type:   node render/cli.js sample samples/hijab-store
    2. Look for:   "ok": true
    3. Optional: open  samples\hijab-store\out\hijab-store.pdf  and look at the Arabic slides.

[ ] TEST 3 - Claude works  (uses a tiny bit of your Claude plan)
    1. In the Terminal type:   claude -p "Reply with the word OK" --model haiku
    2. It should print  OK  within about 20 seconds.
    3. It asks you to log in, or shows an error: see PART 4, problem A.

[ ] TEST 4 - Status of every client  (free)
    1. In the Terminal type:   node pipeline/cli.js list
    2. Each client is listed with its status and steps (done / failed / approved ...).

[ ] TEST 5 - Full real test  (optional; uses Claude; about 30 minutes)
    Do this after big changes, or if you want to be sure the whole chain works.
    1. In the app: "New proposal". Name it e.g.  TEST - <company>. Use a real company website,
       its social links if you know them, the market, the industry, and a few lines of notes.
       Click "Create and start research".
    2. You land on the Research stage. Website audit and meeting notes run first, then several
       steps side by side. Under "Competitors", choose "Compare" or "Not a competitor" for each
       AI suggestion and click "Save decisions" (you can do this while research is still running).
    3. Answer "Important questions" only if some appear.
    4. Competitors & social: profile rows should turn "Captured" and the scorecard fills in.
       A row "Could not read" -> "Try again" later, or "Type numbers".
    5. Diagnosis (about 9 minutes after you started): each problem shows its evidence next to it.
       Confirm or reject each one, then "Approve diagnosis". Scope & plan: "Approve scope".
    6. Proposal: the slides appear about 7 minutes later. Try "Ask the AI to change something" with a
       small change (for example: make the problems title shorter); the answer comes in seconds and the
       slides are redesigned. Tick "I compared every statement..." and click "Approve proposal".
    7. Delivery: the internal strategy report starts at once and is ready about 4 minutes later.
       "What this proposal cost in Claude usage" shows each Claude step.
    8. Finished testing? In the proposals list, click the "..." button on the test row and choose
       "Delete permanently" (or "Archive" to keep it out of the list without losing it).
       A new proposal for the same company later starts fresh either way.


---------------------------------------------------------------
PART 4 - IF SOMETHING GOES WRONG
---------------------------------------------------------------

  A. "Waiting for AI answer", or an AI step failed with a login message
     1. Terminal: type  claude  and press Enter. Log in with the Claude Max account. Type /exit.
     2. In the app click "Try again".
     Still not working? Open Claude Code in the project folder and type  /run-step
     It answers the saved AI request by hand and the pipeline continues.

  B. The black window closes at once, or says "Node.js is not installed"
     Install Node.js 24 from https://nodejs.org , restart the computer, start the app again.

  C. The page http://localhost:4317 does not load
     Is the black window open? If not, start the app (PART 1).
     If the black window shows an error, copy the text and send it to Claude.

  D. An error mentions "chromium" or "Executable doesn't exist" (screenshots / slides fail)
     Terminal:   node node_modules\playwright\cli.js install chromium

  E. TikTok / YouTube: "yt-dlp is not installed"
     Close the app and start it again: it downloads the reader by itself.

  F. Competitors & social: a profile says "Could not read"
     Platforms sometimes refuse for a while. Click "Try again" later.
     Still failing? Use "Type numbers" (type what you see on the profile) or "More" > "Skip this profile".
     LinkedIn needs the COMPANY page link (linkedin.com/company/...), not a personal profile.

  G. Research: "Google search" says Google asked to verify
     Google sometimes refuses automated searches for a while. Add the free SerpApi key on "Settings & keys"
     (250 searches a month) and click "Run again" on that step, or run it again later.

  H. Keys stopped working (PageSpeed, SerpApi, YouTube, Apify, Notion)
     In the app: left menu -> "Settings & keys". Click "Test" next to the key to see what the service says.
     Paste a new key in its box -> "Save keys". It is used at once; no restart needed.

  I. A new Claude model came out, or you want to be sure Claude is current
     Double-click  UPDATE-CLAUDE.cmd  in the project folder. It updates the Claude program, says whether you
     are signed in, and prints the real model that last answered for each job (for example claude-opus-5-5).
     The steps ask for "opus" / "sonnet" / "haiku" (ai/models.js), never a version, so the newest model of
     that family is used automatically once the Claude program knows it.

  J. Anything else: copy the exact message (or a screenshot) and send it to Claude.


---------------------------------------------------------------
PART 5 - WHERE YOUR WORK IS
---------------------------------------------------------------

  - Clients (evidence, diagnosis, approvals, proposals):  C:\dev\al-marketer-automation\clients\
    Final proposal PDFs:  clients\<client>\output\
  - Keys: saved on the "Settings & keys" page, in the file .env.local on this computer. They are never
    uploaded and the page never shows them again. Keep a copy of your keys somewhere safe (for example a
    password manager).
  - Backup: the project, including the clients folder, is copied to your private GitHub
    whenever you ask Claude to "commit and push". Keys are never part of that backup.


---------------------------------------------------------------
PART 6 - NEW OR RESET COMPUTER  (only if Windows was reinstalled)
---------------------------------------------------------------

  1. Get the project back: install Git for Windows (https://git-scm.com) and Claude Code
     (PowerShell:  irm https://claude.ai/install.ps1 | iex ), open Claude Code and ask
       "clone my private al-marketer-automation GitHub backup into C:\dev"
     (or use a package zip made with PART 7, extracted to C:\).
  2. Double-click SETUP.cmd in the project folder. It checks the computer, puts Node.js 24 in the
     project folder if needed, installs the components and the browser, installs Claude Code if
     missing, opens the Claude sign-in (use the Claude Max account), runs a full check and makes the
     Desktop shortcut. Safe to run again at any time.
     Also turn OFF "Help improve Claude" at https://claude.ai/settings/data-privacy-controls
  3. Keys (all optional): in the app, left menu -> "Settings & keys" -> paste each key -> "Save keys".
     Or put your saved API-KEYS.txt into the project folder and click "Import from API-KEYS.txt".
  4. Run TEST 1 from PART 3.


---------------------------------------------------------------
PART 7 - GIVE THE SYSTEM TO SOMEONE ELSE  (a tester or a teammate)
---------------------------------------------------------------

  Two kinds of zip (a terminal in the project folder):
  A. A FULL COPY - works like your own system on the other computer:   npm run package:full
     Everything in the project folder: all proposals (clients), REF, catalog, and your keys
     (.env.local, API-KEYS.txt), so everything works at once. Left out: what SETUP.cmd makes on each
     computer (Node.js, components, downloads), the git history (so the copy cannot push to your
     GitHub backup) and the unused Instagram/Meta keys. Adds PACKAGE-INFO.txt (what is inside).
     Copied to your Desktop: "Al-Marketer FULL copy (<date>).zip" (about 70 MB).
     It holds your keys and client proposals: send it only to that person (a private WhatsApp
     message or a Google Drive link shared with their email), and never post it anywhere.
     Their proposals are a separate copy: nothing is synced between the two computers.
  B. A CLEAN COPY for an outside tester, without your data:   npm run package
     Only the committed files: no keys, no clients folder, no REF folder, no downloads. It stops
     if any saved key value appears in a file. Desktop: "Al-Marketer for testing (<date>).zip" (4 MB).
  Then send the zip. The person opens START-HERE.txt inside it:
     extract to C:\, double-click SETUP.cmd, sign in with THEIR OWN Claude account (Pro or Max).
     Never share your own Claude login or keys.
  If they have a problem, ask for a screenshot and the file setup-report.txt from their folder.
